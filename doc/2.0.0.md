# Versión 2.0.0 — Proyectos redefinidos: configuración y información en JSON

**Fecha**: 2026-07-29

## Resumen

Los proyectos se simplifican y se vuelven flexibles: por un lado la configuración básica, por otro un documento JSON libre donde vive toda la información del proyecto. El agente ya puede leer y modificar esa información pieza por pieza, sin depender de formularios fijos.

## Novedades

- **Vista de dos paneles**: el detalle del proyecto muestra a la izquierda la configuración (nombre, descripción, estado, agente del chat) y a la derecha la información del proyecto en JSON.
- **Información en secciones editables**: el panel de la derecha organiza el JSON en cuatro secciones —historias de usuario, arquitectura, proyectos relacionados y metadatos— cada una con su propio editor y su propio botón de guardar. Puedes formatear el JSON, descartar cambios y ver de un vistazo qué secciones tienen ediciones sin guardar. Si agregas secciones propias, también aparecen en el panel.
- **Estructura libre**: las cuatro secciones siempre existen, pero su contenido lo defines tú. Puedes guardar cualquier estructura que necesite el proyecto sin esperar a que se agregue un campo nuevo al sistema.
- **El agente gestiona la información del proyecto**: se pueden asignar a un agente herramientas para leer, crear, actualizar y eliminar segmentos del JSON, además de actualizar la configuración del proyecto. El agente trabaja sobre una sección completa o sobre un punto exacto dentro de ella (por ejemplo, el estado de la primera historia de usuario), sin reescribir todo el documento.
- **Contexto de chat más completo**: al conversar dentro de un proyecto, el agente recibe el JSON completo del proyecto y las indicaciones para modificarlo.

## Correcciones

- Al eliminar un proyecto ya se eliminan también sus interesados; antes quedaban registros sueltos.

## Notas

- **Antes de actualizar**: respalda la base de datos y ejecuta una vez `npm run db:migrate-proyectos`. Ese comando traslada las historias de usuario y sus comentarios al nuevo JSON de cada proyecto, conserva la arquitectura como parte de la sección correspondiente y guarda en metadatos el lenguaje de programación, el ID de Clarify y los servicios que tuviera registrados. Debe correrse con la versión anterior instalada; si arrancas primero la versión nueva, esos tres campos se pierden.
- **Campos retirados**: ID de Clarify y lenguaje de programación dejan de ser campos del proyecto. No se borran: la migración los conserva dentro de metadatos.
- **Servicios retirados**: la pestaña de servicios y la verificación/escritura automática de `AGENT.md` y `CLAUDE.md` en los repositorios ya no existen. Los servicios que tuvieras quedan como dato informativo en metadatos.
- **Repositorios con archivos generados**: los `AGENT.md` y `CLAUDE.md` que se escribieron en repositorios externos mencionan herramientas que ya no existen (`add_hu_comment`, `update_hu_status`). Hay que editarlos a mano para que apunten a las nuevas herramientas de información del proyecto. `get_proyecto_info` sigue funcionando, así que las sesiones continúan iniciando correctamente.
- **Herramientas retiradas**: `list_historias_usuario`, `add_hu_comment`, `update_hu_status` y el trío de crear/actualizar/eliminar historia de usuario se reemplazan por `read_proyecto_data`, `create_proyecto_data`, `update_proyecto_data`, `delete_proyecto_data` y `update_proyecto`. La migración quita las herramientas viejas de los agentes que las tuvieran asignadas; las nuevas hay que asignarlas explícitamente.
- **Variable de entorno**: `GIT_MCP_SERVER_NAME` ya no se usa y puede quitarse del `.env`.
